# 它自己开始一件事（承诺）——设计

**Goal:** 让 agent 能在没有人开口的那段时间里，把**自己在对话里答应过的事**做完：记下来、
到点做、做完说一声、没做成说清楚。这一步之后，"高度自主"才有主语——是它答应了你，
不是定时任务答应了你。

---

## 1. 问题：现在它为什么会工作

今天只有三个来源：

| 来源 | 触发者 | 例子 |
|---|---|---|
| 对话回合 | 人 | 我说一句，它做一回合 |
| 定时任务 | 人（先设好） | "每天早上看日志" |
| 巡检提议 | 它自己，但只针对**运维事实** | 有失败没人读、队列卡住、会话半途停 |

第三种最接近"自主"，但它看的是**自己的运转状况**，不是**你的事**。它不会因为你周三说了
"这周要整理一下项目"，就在周四想到该动手。

用户的原话是"高度自主的 agent"。自主的核心不是"能自己跑"，而是**它接住一件事、并且
不靠人提醒也会把它推进到底**。

## 2. 设计原则

1. **发起发生在对话里，跟进发生在巡检里。** 人在场的那一刻是唯一有足够上下文判断"这是
   一件事"的时刻；事后读全量对话去猜，既贵又容易猜错。
2. **承诺是一种任务，不是一种新对象。** 调度器已经有到期时间、执行、验收、重试、汇报、
   取消。再建一套只会多一个会漂的副本。
3. **承诺的失败要出声。** 忘记一件答应过的事，比一次运行失败更伤信任——而且更难被察觉。
4. **不制造第二个收件箱。** 承诺进现有的看板和自动化页，不新开一页。

## 3. 核心决策

### 决策一：承诺 = 带 `origin: "commitment"` 的一次性任务

调度任务已经有的字段，承诺全部复用：

| 字段 | 承诺怎么用 |
|---|---|
| `trigger` | `once(at=约定时间)`；"晚点"解析成 +30 分钟，"明天"是次日 09:00 |
| `payload.prompt` | 要做什么，用第一人称写下（"给用户整理一份清单"） |
| `payload.origin` | `"commitment"`——与巡检自己的 `"autonomy"` 并列 |
| `payload.commitment` | `{said: 原话, made_at, due_at, source_session}` |
| `acceptance` | 可选；有验收标准的承诺才做质量判定 |
| `permission_profile` | 与现在一致（无人值守档位；不可逆动作在运行里就会被拒） |

**为什么不用新表**：一个新表要重写一遍到期计算、抢占、租约、重试、汇报。承诺与"一次性
任务"的差别只在**语义标签**和**谁来跟进**，不差在调度。

`origin` 已经有一个用处：`is_own_errand()` 让巡检不去追自己执行的提议的失败。承诺用另一个
值，因为它的跟进策略不同（见决策三）。

### 决策二：发起发生在对话里，用一个窄工具 + 一条提示词规则

新工具（只有一个必填面，比 `schedule_create` 的十一个字段窄）：

```
commit(what: str, when: str = "30m", said: str = "")
  → 建一条 origin=commitment 的一次性任务
  → 返回 {id, due_at}，让它在回复里说清"什么时候"
```

提示词新增一条：

> 当你说"一会儿 / 晚点 / 明天给你 / 我查一下再回你"，这不只是措辞：用 `commit` 把它写下来。
> 没有写下来的"稍后"就是忘记。反问自己：**如果这一轮结束后进程重启，这件事还在吗？**

这条规则是关键。工具本身不难，难的是它**知道要写**。

同一件事重复承诺时去重：若已有一条同目标的 open 承诺，更新它的时间而不是新建。

### 决策三：跟进不新建巡检规则——**实施时发现它没有案子可办**

原计划是加一条巡检规则：承诺到期没跑成 → 重排一次 → 仍未成 → 报告 → 24 小时 → 放弃。
写实现时逐条对了一遍，发现这条规则要处理的情形，现有的两条路径已经各管一头：

| 情形 | 现在谁管 |
|---|---|
| 到期时进程没在跑 | 调度器恢复后**补跑一次**（`missed_run_policy = coalesce`） |
| 跑了但失败 | 运行失败已经在对话里报过（`reports`），原因还经过 diagnostics 归类 |
| 手动触发过 | 跑过即关闭（见决策四），不会再被算作"还欠着" |
| 被停用 | 人主动停的，看板上那条仍然在，只是不会自己跑 |

再加一条巡检，"到点没成"就会有第三个声音说同一句话。所以这一版只做**可见性**：看板上
一组"它答应你的事"，写清目标、还有多久 / 已经晚了多久、当初那句话。

代价说清楚：一条被停用、或调度器长期不在的承诺会一直挂在看板上。这是有意的——它就是
欠着，挂在那里比悄悄消失诚实。

### 决策四：欠着 = 还没被尝试过

"还欠着"不另立字段，读运行历史：**只要有任何一次运行为它发生过，这条承诺就关闭了**——
要么兑现了，要么作为失信被说出来。

第一版用 `next_run_at is not None` 判断，被自己的测试抓到：手动触发的运行不会清掉
`next_run_at`，于是已兑现的承诺被算成还欠着。测试是这么写的，也就这么发现的。

## 4. 生命周期

```
对话里答应
   │  commit(what, when)          ← 工具
   ▼
一次性任务（origin=commitment，到期 at）
   │
   ├─ 到点执行 ──► 成功 ──► 对话里一行 report（"你要的清单好了"）
   │                └─ 失败 ──► report（归类后的原因）+ 重排一次
   │
   ├─ 错过窗口（进程没跑）──► 补跑一次；仍不成 ──► report
   │
   └─ 24h 未完成 ──► dropped + 一句"放弃了"
```

## 5. 与现有机制的关系

| 现有 | 与承诺的关系 |
|---|---|
| 定时任务 | 同一执行路径；区别是**谁发起**（人 vs 它）和**谁跟进**（无 vs 巡检） |
| 巡检提议 | 承诺不走提议：它已经得到过许可（你听它说要去做） |
| `reports` | 承诺的完成/失败走同一条总线，进同一个对话 |
| 失败诊断 | 承诺失败的原因同样进 `diagnostics` 归类；反复失败会触发已有的 repeated-task-failure 规则 |
| Ralph | 承诺是一件事，不是一个迭代目标。需要多轮才能做完的承诺，在它的 prompt 里自行 `/ralph`（本版不自动接） |
| 权限 | 与无人值守一致：不可逆动作在运行里被拒，会以失败承诺的形式说出来 |

## 6. 噪声与失败模式

| 风险 | 处理 |
|---|---|
| **承诺膨胀**（它答应得太多） | 同时 open 的承诺上限（默认 5）；超过时新承诺要求"替换掉一条旧的"，否则不建 |
| **每次承诺都说话** | 只在完成/失败/放弃时说；创建时不说（它刚刚在对话里已经说过了） |
| **重复** | 同目标 open 承诺去重，更新时间 |
| **无止境重排** | 只重排一次 |
| **把不可逆的事当承诺** | 运行档位拒绝；拒绝如实汇报，不会偷偷做 |
| **时区** | 全部走既有 `timezone_name`（默认本地时区），到期时间是绝对时刻 |
| **它承诺了但你没有同意** | 承诺不是许可：它只承诺"我会去做这件事"，做不到会被看见；越权动作仍在运行里被拒 |

## 7. MVP 范围与验收标准

**做**：
1. `commit` 工具（what / when / said），建 origin=commitment 的一次性任务；
2. `commitments` 读工具（open 列表：目标、到期、来源原话）；
3. 提示词规则（"没有写下来的稍后就是忘记"）；
4. 看板新增一组"它答应你的事"（还欠着的承诺，目标 + 到期/逾期），不可点（没有详情页）；
5. 上限 5 条 + 同目标去重。

**已落地**：`87c65fe`（工具 + 提示词）、`ab33328`（看板一组）。巡检规则按决策三不加。

**验收（都能写成测试）**：
- [x] 一个脚本化模型在对话里调用 `commit`，落库的是 `origin=commitment` 的一次性任务
      （`test_promising_something_writes_it_down_as_a_commitment`）；
- [x] 同目标两次承诺 → 只有一条（更新到期时间）；
- [x] 超过 5 条 open 时第 6 条被拒；
- [x] 读不懂的时间被拒绝而不是猜；
- [x] 跑过即关闭（承诺不再算"还欠着"）；
- [x] 看板的"它答应你的事"只列承诺、按到期排序、逾期/剩余文案正确；
- [ ] 承诺完成时的 report —— 复用既有运行汇报（`test_web_ui_e2e.py` 里那条），承诺没有
      单独的汇报路径，所以不重复测；
- [ ] 24h 放弃 —— 不在本版（见决策三）。

## 8. 明确不做

1. **不让巡检读全量对话去找"该做的事"**：每个 tick 都调一次模型、且判断质量取决于摘要，成本
   与误报都不划算。发起留在对话里。
2. **不新建"承诺页"**：看板一组 + 自动化页的列表足够。
3. **不自动接 Ralph**：多轮目标先由它自己在 prompt 里决定。
4. **不做"它自己定目标"**：这是下一个问题，答案不该长在承诺上。

## 9. 开放问题

1. **"晚点"到底多晚？** 30 分钟是拍脑袋。可以按对话节奏（最近活跃时间）推断，也可以直接问
   一句"多久后提醒你"。MVP 先 30 分钟，并在回复里说出来，让人可以纠正。
2. **承诺失败后要不要自动改做法？** 现在只报告。若 repeated-task-failure 先触发，会给出
   "改设置"的提议——两条路径会不会重复说话？MVP 接受这一点，观察后再合并。
3. **承诺的可见性**：看板一组够不够，还是需要在对话里常驻一行"它还欠你 2 件事"？先看使用。
