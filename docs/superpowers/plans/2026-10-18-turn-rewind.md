# 回退最后一轮：重新生成与编辑重发

2026-10-18 · 设计记录，先于代码。这是「对话页交互」里一直没有做的那一项：A 批次做了深链和工具轨迹，把「重新生成 / 编辑重发」单列，因为它需要的不是前端改动，而是一个历史回退原语。

## 要解决的问题

一轮对话在三个地方各有一份：

1. **持久对话记录**（`conversation_turns` + `agent_events`，按 `seq` 排在同一条时间线上）——浏览器画出来的那份；
2. **provider 重放尾**（`provider_checkpoints` 里的一串 provider 消息）——会话被驱逐或进程重启后，`ctx.messages` 由它重建；
3. **活的请求历史**（`RuntimeSessionState.ctx.messages`）——当前进程里下一次请求实际发送的那份。

只删其中任意一份都不是回退：删记录而 provider 还记着，下一轮会把删掉的内容再送上去；清 provider 而记录还在，刷新就打回原形。所以原语必须同时切三处，且切在**同一个位置**：这一轮的请求消息。

## 语义（v1）

- **只回退最后一轮**。中间一轮会留下它之后的每一轮在回答一个已经不存在的上下文——那是分支（branch），不是截断，需要另一套设计。
- **什么时候允许**：会话空闲、重启队列为空。正在跑的轮次直接拒绝（409）：从活轮次脚下抽掉历史，是唯一不能出现的竞态。
- **切在哪**：这一轮的用户消息。请求消息不是纯文本——这一轮的检索上下文在它前面、附件上下文在它后面——所以按**包含**匹配；按位置从新往旧找，只认 `role == "user"` 且不是 `tool_result` 块、不是插话（`<user_interjection>`）的消息。工具结果和插话在某些 provider 格式里也以 user 角色出现，匹配到它们就会切在轮次中间。
- **provider 尾被压缩过怎么办**：找不到请求就**不动它**。那一轮已经只存在于摘要里，在更早的位置截断会删掉**另一轮**。此时回退仍会切记录和活上下文，效果等于「把这句话再问一遍」——降级，但不是错的。
- **活上下文找不到请求**：同理不动。压缩把它变成摘要了，模型对它的记忆本来就是摘要。

### 明确不碰的三样

- **长期记忆**（facts / entries）：回退说的是「让我再看看这一轮」，不是「忘掉你从中学到的东西」。用户改一句话，不应该让 agent 忘掉一个事实。
- **待整合缓冲**（staging）：同上；已整合的记忆保留，未整合的仍会由下一轮继续。
- **会话任务状态**（`session_working_state`）：任务有没有完成和「这句话要重说」无关。

代价写在这里而不是藏着：从被回退那一轮整合出来的记忆会留在记忆里。

## 接口

`POST /api/sessions/{id}/rewind`

- `200 {"ok": true, "user_text": "...", "message_id": "...", "seq": N, "removed_turns": n, "removed_events": m, "checkpoint_messages_removed": c, "live_messages_removed": l}`
- `409` 轮次在跑；`404` 没有可回退的一轮。

`user_text` 必须由服务端返回：客户端不能猜服务端切掉了哪一轮。

客户端流程：

- **重新生成**：`rewind` → 用返回的文本调 `sendMessage(text)`；
- **编辑**：`rewind` → 把文本放回输入框并聚焦，**不发送**。改完由用户自己按发送。
- 回退后客户端重新拉取记录，而不是本地删行：切按位置进行，客户端手上的乐观行没有位置。

## 为什么不是别的做法

- **在客户端截断并重发**：provider 那一份不知道，下一轮把删掉的上下文又带上——看起来成功，实际重复。
- **给每条消息记 provider 下标**：压缩会重写 `ctx.messages`，下标失效。按请求文本匹配是唯一在压缩前后都成立的锚点。
- **把整段上下文从记录重建**：记录是展示层（没有工具调用结构），重建会改变模型看到的历史，代价比收益大。

## 已知的、可接受的偏差

- 侧栏的「N 轮」来自 `state.turn_count`，是「执行过的轮次」，回退不递减——递减会让下一轮的 `turn_id` 与旧轮重复。它和记录里的轮数在回退后会不一致；记录才是真相。
- 打开着同一个会话的其它标签页不会自动刷新（回退只由发起方重新拉取）。多标签广播是后续工作。

## 证据

- `tests/test_session_rewind.py`：三份副本各自切开、压缩尾不切、插话跳过、运行中拒绝、空会话返回 None。
- `tests/test_web_channel.py`：端点返回被切的原文、连续回退逐轮进行、运行中 409。
- 真实网关（两次模型调用）：单轮回退后重放尾 2 条无重复；多轮回退后保留第一轮、第二轮的旧回答被替换，重放尾 4 条无重复。
